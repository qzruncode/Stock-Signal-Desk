## Page Function Map

`docs/project-map/` is the human control surface for frontend page behavior. It is not a changelog and not a design essay. Each page md must be reconstruction-grade: another AI should be able to rebuild the page behavior from the md alone, including exact visible text, controls, data sources, endpoints, consumed fields, storage/cache, state transitions, render branches, empty/error states, similar functions, and differences.

- Use `.claude/skills/dev` when the user invokes `/dev`, asks for a short Human Plan before implementation, or wants Human Plan approval followed by AI-only Execution Plan execution.
- Use `.claude/skills/code-governance-audit` when the user asks to scan the project and produce a prioritized code governance modification list.
- Use `.claude/skills/project-map` when the user asks to initialize/update/visualize page function docs or run a requirement/design check from those docs.
- Manual calls include `/project-map init`, `/project-map update`, `/project-map visualize`, and `/project-map check`.
- When adding a new frontend page or route, create/update the matching page function md as part of the work unless the user explicitly says not to.
- When changing an existing page, read the matching page md first if it exists, then update it and the visual maps after the code change so they reflect the full current page behavior.
- `/project-map visualize` must generate a browser-openable interactive flowchart under `docs/project-map/visual/index.html`, not markdown summary files or a force-directed node cloud.
- Page md content must focus on exact page behavior only: user action, trigger condition, visible output, exact copy, data fields, backend endpoint, request params, response usage, storage/cache, state transitions, render branches, empty state, error state, navigation, preconditions, similar functions, and differences.
- Do not add `最近变更`, TODOs, implementation notes, or generic principles to page md files.
- Do not delete or rewrite `docs/project-map/` unless the user explicitly asks. It may be an in-progress artifact generated by the user or by `/project-map init`.

## Code Rules

- Keep production `apps/dsa-web/src/**/*.ts(x)` files under 600 lines. Exclude test files.
- Page files should orchestrate data and layout only. Move reusable UI into `components/**`.
- Move state machines, timers, subscriptions, polling, and localStorage logic into hooks or utils.
- Do not create components inside render functions.
- Component files should export components only; shared helpers belong in `utils/**` to keep Fast Refresh clean.
- Route-level lazy loading already exists in `App.tsx`; keep heavy page dependencies behind route chunks.

- Run `npm run check:constraints` in `apps/dsa-web` after structural frontend changes.
- Production page chunks should stay below 150 KiB uncompressed.
- Vendor chunks should stay below 260 KiB uncompressed.
- If a budget is exceeded, split the feature or move heavy dependencies behind lazy boundaries.
