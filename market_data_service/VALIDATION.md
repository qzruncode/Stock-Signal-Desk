# 数据服务验收记录

## 2026-09-07：事件驱动改造（当前验收）

本轮针对页面高频刷新、重复等待查询、全量明细计算和日线重复全窗口采集做整体调整。实现说明见 [EVENTS.md](EVENTS.md)。下方历史阶段的测试数量和性能快照不代表本轮重复执行结果。

### 已落地的行为

- PostgreSQL 事务待发送记录和 `LISTEN/NOTIFY` 驱动独立事件维护进程；汇总提交后通过 Redis Streams 投递。回滚不发事件，未发送记录可在故障恢复后继续处理，允许重复投递。
- 页面使用一个 SSE 订阅，汇总直接更新查询缓存；只对受影响的已打开明细按需查询。概览、任务列表、覆盖明细和任务详情的固定刷新间隔均已移除。
- 概览读取持久化的小体积汇总，覆盖明细由数据库过滤、计数和分页。只更新受影响证券或来源订阅的查询投影。
- 首次或过期业务读取在一次 HTTP 请求内有界等待相关事件；任务进度复用 `httpx-sse`。不再使用循环提交请求或每 250 毫秒查库。
- 日线复用来源日期窗口 API 做重叠增量校验；前复权价格变化、来源切换、覆盖缺失或周期校验时回到完整窗口。行情常规刷新避开非交易时段。
- 浏览器原生网络事件识别离线状态，保留旧快照并禁用同步；复用 `reconnecting-eventsource` 处理临时 HTTP 503 后原生连接不再重连的边界。重连游标兼容标准请求头与库的查询参数。
